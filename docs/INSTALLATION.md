# Installation

Everything here was worked out by hand against real Samsung TV hardware (an
older 2018 4K set and a newer 2022 QLED), so it includes the non-obvious steps
and dead ends, not just the happy path.

## 1. Install Tizen Studio

Download and install [Tizen Studio](https://developer.tizen.org/development/tizen-studio/download)
(the base installer is enough to start). On Windows it defaults to
`C:\tizen-studio`, referenced throughout `scripts/*.ps1` and below — adjust the
paths if you installed elsewhere.

### Package Manager repository may be dead

Tizen Studio's Package Manager may ship with a default **Package Repository**
URL that no longer resolves (`http://usa.sdk-dl.tizen.org/...` returned a
plain `403 Forbidden` when we hit it). If Package Manager shows "Cannot
connect the repository server":

1. Open Package Manager → the gear/settings icon → **Configuration**.
2. Replace the **Package Repository** URL with:
   ```
   http://download.tizen.org/sdk/tizenstudio
   ```
3. Click **Apply** — the version/snapshot list should populate.

### Install the full IDE + Certificate Manager

The base install only gets you the CLI tools. To create a real Samsung
certificate (required — see step 3) you need the **Certificate Manager**,
which in turn needs the full Eclipse-based IDE:

1. Package Manager → **Main SDK** tab → tick "View installed packages" and
   confirm/install **Certificate Manager**.
2. Package Manager → **Extension SDK** tab → install **Samsung Certificate
   Extension** (this unlocks the Samsung-certificate option; without it,
   Certificate Manager only offers generic Tizen test certificates).
3. This also installs the full IDE at `C:\tizen-studio\ide\TizenStudio.exe`.

## 2. Create the author certificate (CLI, one-time)

A local, self-signed author certificate — doesn't need any account:

```powershell
& "C:\tizen-studio\tools\ide\bin\tizen.bat" certificate `
  -a IptvAuthor -p <a-password> -c IT -s "State" -ct "City" `
  -o "Personal" -u "Dev" -n "Your Name" -e "you@example.com" -f iptv-author
```

This writes `iptv-author.p12` under `C:\tizen-studio-data\keystore\author\`.

## 3. Create a Samsung certificate (GUI, required for real TVs)

This is the step that's easy to skip and then spend a long time debugging a
generic `Failed to install Tizen application` error for. **Every distributor
certificate that ships with or is CLI-default-generated by Tizen Studio — the
"sample" one, even the non-expired renewed one — only works on the Tizen
Emulator, not on a retail Samsung TV.** Real hardware requires a certificate
that embeds the TV's **DUID** (Device Unique Identifier) and is issued through
a (free) Samsung account.

1. Put the TV in **Developer Mode**: on the TV, open the **Apps** panel, type
   `12345` on the on-screen number pad → a "Developer mode" menu appears.
   Turn it on, set **Host PC IP** to this computer's LAN IP, and restart the TV
   when prompted.
2. Connect the TV over the network from this PC:
   ```powershell
   & "C:\tizen-studio\tools\sdb.exe" connect <tv-ip>:26101
   ```
3. Open `C:\tizen-studio\ide\TizenStudio.exe` → **Tools → Certificate Manager**.
4. Click **+** next to "Certificate Profile" → walk through the wizard:
   - Author Certificate → **Select an existing author certificate** → the
     `iptv-author.p12` from step 2.
   - Distributor Certificate → **Create a new distributor certificate** →
     Privilege: **Public** (Partner requires a business/partner Samsung
     account, not needed here) → log in with any Samsung account → the
     connected TV's DUID should appear in the device list automatically —
     check it (and any other TV you've also connected via `sdb connect`) →
     set a password.
5. Note the profile name the wizard created (shown in Certificate Manager's
   profile list) — you'll need it in step 4.

**If you have more than one TV**, connect all of them via `sdb connect` first,
*then* run the wizard once so every DUID gets embedded in the same
certificate — redoing the wizard per-TV creates separate certificates and
separate profiles to keep track of.

## 4. Wire the certificate into the build script

Edit `scripts/build.ps1` and set:

```powershell
$ProfileName = "<your-profile-name-from-step-3>"
```

## 5. Build and install

```powershell
.\scripts\build.ps1
.\scripts\deploy.ps1 -Tv <tv-ip>
```

`deploy.ps1` connects to one TV over `sdb` and installs the freshly built
package. To install on more than one TV, run it again with a different
`-Tv` — this is the common case in practice, so the script deliberately
targets one TV per run rather than juggling a list.

## Troubleshooting

**`Failed to install Tizen application` with no further detail.** Almost
always a certificate problem, in roughly this order of likelihood:

1. You're signing with the CLI's default distributor certificate, not a
   Samsung certificate with the TV's DUID (see step 3). This was the root
   cause every time in our testing — including once with a certificate that
   was valid, non-expired, and even correctly-DUID-bound-*sounding*, so don't
   assume yours is right just because it "should" be; check the certificate
   really is the DUID-bound Samsung one, not a leftover Tizen test profile.
2. A **different app** is already installed under the same 10-character
   `package` id (see `config.xml`'s `tizen:application package="..."`)
   signed with a *different* certificate. Tizen refuses to silently replace
   an app signed by someone else. Uninstall it first:
   ```powershell
   & "C:\tizen-studio\tools\ide\bin\tizen.bat" uninstall -p <full-app-id> -t <target>
   ```
   Note **`-p` wants the full app id** (e.g. `APPIPTV001.IPTVPlayer`, the
   `tizen:application id` attribute), not the bare 10-character `package`
   value — passing the package value alone just gets you a misleading
   "package is not exist" instead of finding the real one.
3. The app's `<name>` in `config.xml` contains a **space**. This alone was
   enough to make every install attempt fail identically on both a 2018 and a
   2022 TV, regardless of certificate correctness — it took a binary-search
   through a from-scratch minimal test app to isolate. Keep it a single
   word/CamelCase (this project uses `IPTVPlayer`).

**The TV's SDB port (26101) refuses connections / times out.** The TV was
probably rebooted or the "Host PC IP" field is stale. Reboot the TV once after
confirming Developer Mode + Host PC IP are set, then retry `sdb connect`.

**`sdb shell` / `sdb dlog` return `closed` immediately, or nothing.** Expected
on retail TVs — interactive shell and log access are locked down (unlike the
Tizen reference boards/emulator). There's no way to get native platform logs
from these TVs short of on-screen debugging inside the app itself (this
project's in-player debug overlay exists for exactly this reason).
